1. ¿Qué es XML?

XML significa Extensible Markup Language (lenguaje de marcado extensible). Es un formato de texto que permite representar, organizar, almacenar e intercambiar datos usando etiquetas creadas para describir la información.

Ejemplo de idea: en vez de guardar solamente María, 17, Bogotá, podemos etiquetar cada dato como <nombre>, <edad> y <ciudad> para que su significado sea explícito.

¿Para qué se usa?

  • Intercambiar información entre aplicaciones y sistemas.
  • Representar configuraciones y catálogos de datos.
  • Guardar documentos estructurados, feeds y algunos formatos de oficina.
  • Servir como base para formatos especializados, por ejemplo SVG y RSS.

Ventajas: es legible, estructurado, independiente de una plataforma y permite crear vocabularios propios. Consideración: suele ser más verboso que formatos como JSON.

2. Sintaxis esencial de XML

ReglaExplicaciónEjemplo
Un solo elemento raízTodo el documento debe estar dentro de un elemento principal.<curso>...</curso>
Etiquetas de apertura y cierreEl nombre debe coincidir exactamente.<nombre>Ana</nombre>
Anidamiento correctoLas etiquetas deben cerrarse en orden inverso al que se abrieron.<a><b>dato</b></a>
Distingue mayúsculas<Nombre> y <nombre> son etiquetas distintas.Usar el mismo nombre al cerrar.
Atributos entre comillasLos valores de atributos van entre comillas simples o dobles.<alumno id="A01"/>
Etiquetas vacíasUna etiqueta sin contenido puede cerrarse con />.<telefono/>
Caracteres especialesEn texto, escapa & y < cuando sean datos.&amp;, &lt;

Estructura general

<?xml version="1.0" encoding="UTF-8"?>
<raiz>
    <elemento atributo="valor">Contenido</elemento>
</raiz>

La declaración XML inicial es común y útil, aunque no siempre es obligatoria. XML organiza datos; por sí solo no define cómo se verán en pantalla.

Recuerda: un documento bien formado cumple las reglas de sintaxis. Un documento válido, además, cumple las reglas de una estructura definida por un DTD o un esquema como XML Schema (XSD), cuando se usa uno.

3. Cinco ejemplos básicos

Observa cómo cada ejemplo tiene una raíz y etiquetas que describen su contenido.

Ejemplo 1 · Saludo

<saludo>¡Hola, mundo!</saludo>

Un elemento raíz llamado saludo contiene texto.

Ejemplo 2 · Persona

<persona>
  <nombre>Laura</nombre>
  <edad>20</edad>
</persona>

Una persona con dos datos sencillos.

Ejemplo 3 · Atributos

<producto codigo="P15" disponible="si">
  Teclado
</producto>

Los atributos agregan información a la etiqueta de apertura.

Ejemplo 4 · Lista simple

<colores>
  <color>Azul</color>
  <color>Rojo</color>
  <color>Amarillo</color>
</colores>

Un mismo tipo de etiqueta puede repetirse dentro de la raíz.

Ejemplo 5 · Caracteres especiales

<mensaje>
  Pan &amp; café cuestan menos
  que &lt; 10000 pesos.
</mensaje>

En el contenido, &amp; representa & y &lt; representa <.

4. Cinco ejemplos anidados

Los elementos anidados representan relaciones de pertenencia. Cada elemento hijo debe quedar completamente dentro de su elemento padre.

Ejemplo 1 · Estudiante

<estudiante id="E07">
  <datosPersonales>
    <nombre>Samuel Ríos</nombre>
    <correo>samuel@ejemplo.com</correo>
  </datosPersonales>
  <programa>Sistemas</programa>
</estudiante>

Separa datos personales de información académica.

Ejemplo 2 · Biblioteca

<biblioteca>
  <libro>
    <titulo>Viaje al centro</titulo>
    <autor>
      <nombre>J. Verne</nombre>
    </autor>
    <publicacion>1864</publicacion>
  </libro>
</biblioteca>

El autor contiene a su vez un elemento nombre.

Ejemplo 3 · Tienda

<pedido numero="1008">
  <cliente>
    <nombre>Camila</nombre>
    <ciudad>Cali</ciudad>
  </cliente>
  <items>
    <item>
      <producto>Cuaderno</producto>
      <cantidad>3</cantidad>
    </item>
  </items>
</pedido>

Representa un pedido, el cliente y sus artículos.

Ejemplo 4 · Horario

<horario>
  <dia nombre="lunes">
    <clase>
      <asignatura>Programación</asignatura>
      <horaInicio>08:00</horaInicio>
      <horaFin>10:00</horaFin>
    </clase>
  </dia>
</horario>

El atributo identifica el día y los hijos describen la clase.

Ejemplo 5 · Empresa

<empresa>
  <departamento nombre="Tecnología">
    <empleado id="A12">
      <nombre>Andrés</nombre>
      <cargo>Analista</cargo>
    </empleado>
    <empleado id="A13">
      <nombre>Diana</nombre>
      <cargo>Desarrolladora</cargo>
    </empleado>
  </departamento>
</empresa>

Una colección de empleados dentro de un departamento.

5. Ejemplos para identificar errores

Antes de mirar la solución, intenta encontrar el problema en cada fragmento. Los errores de esta sección son de sintaxis o de buena formación.

Error 1.
<nombre>Lucía</Nombre>
Ver explicaciónXML distingue mayúsculas y minúsculas. Debe cerrarse con </nombre>.
Error 2.
<ciudad>Medellín
<pais>Colombia</pais>
Ver explicaciónFalta </ciudad> antes de iniciar o finalizar el siguiente elemento. Una corrección es <ciudad>Medellín</ciudad>.
Error 3.
<persona>
  <nombre>Leo</persona>
</nombre>
Ver explicaciónLas etiquetas se cierran en orden incorrecto. Cierra primero nombre y después persona.
Error 4.
<nombre>Sara</nombre>
<edad>19</edad>
Ver explicaciónEl documento tiene dos elementos al nivel superior. Envuélvelos en una sola raíz, por ejemplo <persona>...</persona>.
Error 5.
<curso nivel=basico>XML</curso>
Ver explicaciónEl valor del atributo debe ir entre comillas: nivel="basico".
Error 6.
<empresa>Sol & Luna</empresa>
Ver explicaciónEn texto normal, representa el ampersand como &amp;: Sol &amp; Luna.

8. Cinco retos: escribe el código

Redacta el XML de cada situación en tu editor. Comprueba que esté bien formado con uno de los validadores anteriores. No se incluyen soluciones para que puedas practicar.

1
Ficha personal. Crea un documento con una raíz persona que contenga nombre, apellido, edad y ciudad. Agrega el atributo id a la raíz con un valor entre comillas.
2
Catálogo de productos. Crea una raíz catalogo con tres productos. Cada producto debe tener los elementos nombre, precio y categoría, además de un atributo codigo único.
3
Horario de clases. Representa una semana con al menos dos días. Dentro de cada día incluye dos clases y, para cada clase, asignatura, hora de inicio y hora de finalización. Usa un atributo para identificar el día.
4
Pedido de una tienda. Diseña un pedido con número de pedido, datos del cliente y una lista de al menos tres artículos. Cada artículo debe incluir nombre, cantidad y precio unitario. Usa una estructura anidada clara.
5
Biblioteca escolar. Crea un documento con una raíz biblioteca y tres libros. Cada libro debe contener título, autor (con nombre y apellido anidados), año de publicación y disponibilidad. Añade un atributo identificador a cada libro.
Lista de verificación antes de entregar:
  • ¿Hay una sola raíz?
  • ¿Todas las etiquetas están cerradas y bien anidadas?
  • ¿Los nombres de apertura y cierre coinciden, incluyendo mayúsculas?
  • ¿Los valores de los atributos están entre comillas?
  • ¿Escapaste los caracteres especiales cuando corresponde?
