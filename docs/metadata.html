1. ¿Qué son los metadatos?

Los metadatos son datos que describen otros datos o un recurso de información. Documentan características como su nombre, contenido, autoría, formato, fecha de creación, estructura, procedencia, permisos o forma de uso.

Dato o recurso

El objeto que queremos describir: una fotografía, un documento, una tabla de ventas, un conjunto de mediciones o un archivo de audio.

Metadato

Una característica que ayuda a interpretar, localizar o administrar ese objeto: título, fecha, formato, autor, unidad de medida o licencia.

2. ¿Para qué sirven?

Encontrar

Buscar recursos por título, autor, tema, fecha, lugar o palabras clave.

Interpretar

Comprender qué representa un dato, en qué unidad se mide y bajo qué condiciones se obtuvo.

Administrar

Controlar versiones, responsables, permisos, formatos, estados y fechas de actualización.

Intercambiar y conservar

Facilitar que sistemas diferentes interpreten los recursos y que los archivos sigan siendo utilizables a largo plazo.

Ejemplo en análisis de datos

Una columna llamada temperatura es ambigua si no se conoce la unidad, el lugar o el periodo de medición. Metadatos como unidad: °C, estación: Norte y frecuencia: horaria ayudan a evitar interpretaciones equivocadas.

3. Tipos de metadatos

No existe una única clasificación universal para todos los sectores. La siguiente es una clasificación práctica, habitual en bibliotecas digitales, archivos y gestión de datos. Un mismo elemento puede cumplir varias funciones según el contexto.

3.1 Descriptivos

Describen el contenido y ayudan a identificar, descubrir, buscar y recuperar un recurso.

Ejemplos: título, autor, tema, resumen, palabras clave, fecha de publicación, idioma e identificador.

Pregunta que responden: ¿qué es este recurso y cómo lo encuentro?

3.2 Estructurales

Explican cómo se organizan las partes de un objeto digital y qué relaciones existen entre ellas.

Ejemplos: capítulos de un libro, orden de páginas escaneadas, relación entre un video y sus subtítulos, archivos que componen un expediente.

Pregunta que responden: ¿cómo está compuesto y cómo se relacionan sus partes?

3.3 Administrativos

Ayudan a gestionar un recurso durante su ciclo de vida. En muchos marcos incluyen o se desglosan en metadatos técnicos, de derechos, de origen y de preservación.

Ejemplos: responsable de custodia, fecha de ingreso al repositorio, restricciones de acceso, política de conservación.

Pregunta que responden: ¿cómo se gestiona y bajo qué condiciones puede usarse?

Nota: las categorías se pueden solapar. Por ejemplo, la fecha de creación de una fotografía puede ser descriptiva para una búsqueda y técnica cuando documenta el proceso de captura. La clasificación depende del propósito y del esquema utilizado.

4.2 JSON

Formato de texto que representa objetos mediante pares clave-valor. Es común en API y aplicaciones web.

{
  "titulo": "Registro de cosecha",
  "creador": "Equipo de campo",
  "fecha": "2026-10-12",
  "formato": "application/json",
  "idioma": "es"
}

Cómo leerlo: las claves identifican los campos; los valores contienen la información. Las comillas, llaves y comas deben respetar la sintaxis JSON.

4.3 XML

Lenguaje de marcado que representa la información con etiquetas anidadas. Se usa en numerosos estándares documentales y bibliográficos.

<recurso>
  <titulo>Registro de cosecha</titulo>
  <creador>Equipo de campo</creador>
  <fecha>2026-10-12</fecha>
  <formato>application/json</formato>
</recurso>

En XML, las etiquetas delimitan los elementos y su anidamiento permite expresar relaciones jerárquicas.

4.4 SQL y catálogos de bases de datos

Los gestores de bases de datos almacenan metadatos sobre tablas, columnas, tipos, restricciones, índices y relaciones. En SQL, el esquema de una tabla documenta parte de su estructura.

CREATE TABLE cosecha (
  id INTEGER PRIMARY KEY,
  fecha DATE NOT NULL,
  peso_kg DECIMAL(8,2) NOT NULL,
  lote_id INTEGER
);

El nombre de cada columna, su tipo, la clave primaria y las restricciones son metadatos estructurales del modelo de datos. La descripción del significado de cada campo suele documentarse además en un diccionario de datos.

4.5 Estándares y esquemas conocidos

Dublin Core

Conjunto de elementos generales para describir recursos. Incluye título, creador, tema, descripción, fecha, tipo, formato, identificador, idioma y derechos, entre otros.

Uso típico: repositorios, bibliotecas digitales y publicación de recursos.

METS

Esquema XML para codificar y agrupar metadatos descriptivos, administrativos y estructurales de objetos digitales complejos.

Uso típico: intercambio y gestión de objetos digitales en repositorios.

MODS

Esquema XML de descripción bibliográfica, con más detalle que Dublin Core y una estructura más legible que los códigos numéricos de MARC.

Uso típico: bibliotecas y colecciones bibliográficas digitales.

PREMIS

Diccionario de datos y modelo para metadatos de preservación digital: objetos, eventos, agentes y derechos relacionados con la preservación.

Uso típico: documentar integridad, acciones de preservación y trazabilidad de objetos digitales.

4.6 Ejemplo mínimo de Dublin Core

<dc:title>Guía de cultivo de café</dc:title>
<dc:creator>Equipo técnico</dc:creator>
<dc:subject>Caficultura</dc:subject>
<dc:date>2026-10-12</dc:date>
<dc:language>es</dc:language>
<dc:type>Text</dc:type>

Los nombres anteriores corresponden a elementos habituales de Dublin Core, pero un documento XML válido también debe declarar el espacio de nombres y cumplir la sintaxis del esquema o perfil de aplicación adoptado.

Regla para recordar: Dublin Core ayuda a describir; METS organiza y empaqueta metadatos y archivos; MODS ofrece descripción bibliográfica detallada; PREMIS documenta aspectos de preservación digital. No son formatos intercambiables ni resuelven exactamente el mismo problema.

6. Calidad y buenas prácticas

  • Claridad: usar nombres y descripciones comprensibles; evitar abreviaturas sin explicar.
  • Consistencia: usar un formato uniforme para fechas, unidades, nombres y categorías.
  • Completitud: incluir los campos necesarios para el uso previsto, sin recopilar información innecesaria.
  • Exactitud: comprobar que los valores representan correctamente el recurso.
  • Interoperabilidad: adoptar estándares o documentar cómo se corresponden los campos propios con otros esquemas.
  • Identificadores persistentes: cuando aplique, asignar identificadores estables y únicos.
  • Control de cambios: documentar responsables, fechas, versiones y transformaciones relevantes.
  • Privacidad y seguridad: evitar incluir datos personales o credenciales innecesarias; controlar quién puede consultar o modificar los metadatos.

Preguntas para diseñar un conjunto de metadatos

  1. ¿Qué recurso o conjunto de datos se va a describir?
  2. ¿Quién necesita encontrarlo, interpretarlo o administrarlo?
  3. ¿Qué información mínima es necesaria para esos usos?
  4. ¿Hay un estándar que convenga adoptar?
  5. ¿Cómo se validarán los valores y se actualizarán los metadatos?
